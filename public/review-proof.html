SyncifyPro — proof of resolution

App Store review feedback of 8 September 2026 (requirement 2.1.1). Both reported problems are fixed and live in production.

The reviewer reported:

The import is failing to complete the complete files and also when trying to download or open the file a message "connection was reset" is shown, this also happens when trying to download the exported file.

1. "Connection was reset" when downloading a file Fixed

Cause. Every download link pointed straight at the app's object storage on *.r2.cloudflarestorage.com. That host is reachable from most networks but was reset on the review environment's network, so the embedded app showed the browser's error page instead of a file.

Change. Files are now served by the app itself, from its own domain: https://app.syncifypro.app/files/<token>. The token is signed and expires after one hour, exactly like the storage link it replaces; the app streams the file server-side and sets the download filename. No third-party host is involved in a download any more. This covers every file the app hands out: export results, uploaded import files and import result workbooks.

2. Import not completing on a Shopify-format product CSV Fixed

Cause. Shopify's own Products → Export CSV writes one row per variant and per image, repeating the product handle and leaving most columns blank on those extra rows. The importer treated each row as a separate product, so the rows belonging to one product were written concurrently and Shopify rejected most of them with "This product is currently being modified. Please try again later." A second defect in the same file layout: option names appear only on a product's first row, so variants on the following rows were sent without an option name and Shopify rejected the product.

Change. When a file has no explicit record marker, rows are now grouped into one record per product (matching handle or ID, plus rows that carry no identifier of their own), variant rows inherit the option names from their product's first row, and a write that hits Shopify's transient product lock is retried with backoff.

Recording of the fixed flow

Thirty seconds, production app, real store. A Shopify-format product CSV is imported from a URL, the file is analysed, imported, and the results workbook is downloaded — the step that previously failed.

How to retest

  1. In the Shopify admin, open Products → Export and export as plain CSV. (Or use this sample, which has the same layout: shopify-products-sample.csv.)
  2. Open SyncifyPro, drop that file on Import (or paste the sample's URL into Direct URL and press Import from URL).
  3. Check the analysis: the row count stays as in the file, while Records shows one per product.
  4. Press Import. It finishes with 0 failed.
  5. Press Download results. The workbook downloads from app.syncifypro.app.
  6. Press Import again and repeat — the second run also finishes with 0 failed.
  7. Any export works the same way: Export → pick Products → Export → Download.
